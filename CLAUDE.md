# SheikahPhone

Vue 3 + Vite + TypeScript PWA: a Sheikah Slate for a Zelda-themed scavenger hunt in Ludwigsburg. UI text is German, code and comments are English.
Target: Android Chrome, installed as a PWA, used outdoors and often offline. iOS is out of scope.

## Commands

- `npm run dev` / `npm run build` (type-check + build)
- `npm run check`: type-check, lint and unit tests. Run it before finishing any change.
- `npm run format`: Prettier

## Layout

- `src/views/apps/*App.vue`: the three apps (map, camera, media). Thin: UI only.
- `src/composables/`: browser-API wrappers (`useGeolocation`, `useHeading`, `useCamera`, `useInstall`, `useMotion`, `useBoot`). `useYigaMode` holds the app mode, `useYigaTrigger` (mounted in `App.vue`) wires zone + flip + shake to it.
- `src/lib/`: pure functions with unit tests (`geo.ts`, `zone.ts`, `gesture.ts`). Put new maths here, test it.
- `src/game/`: game content as data (`markers.ts`: all map content, see below; Yiga zone, app registry per mode). Riddles, keys and targets go here, never hardcoded in components.
- `src/map/`: MapLibre style (BotW look) on OpenFreeMap vector tiles. Public service without guarantee: self-host as PMTiles before the real hunt.

- `src/components/PhoneFrame.vue`: the ornamental frame (4 corners + tiling top/bottom strip), two layers: `frame/stone/*` (gold and black, as is) and `frame/glow/*` (white, alpha = glow strength) above it, colored by `--frame-glow` (default `--color-primary`) through a CSS mask, so blue/red needs no extra files. An app can recolor it while it is mounted with `useFrameGlow` (the scanner: `--color-purple`); the frame sits outside the router view, so it goes through a property on <html>. Geometry lives in `src/assets/scss/_frame.scss`. Both sets share names and pixel sizes; `glow/back.png` (the old back-button circle) is unused. The files are currently rough placeholders auto-split from `background/original.png` (blue = glow); if you replace them, keep the sizes in `_frame.scss` in sync (CSS multiplies intrinsic size by `--u`) and `$ext` if the format changes.
- `src/components/BackButton.vue`: the blue arrow (`ui/arrow-left.png`) on the left edge. Every app renders its own (there is no global one), so it enters with that app's UI and its animation (`MapApp`: inside the `App-ui` layer; the others: inside the faded `App`). It goes back in the history (so device back does not return to the app just left) and falls back to home when there is no in-app history. Tinted red in Yiga mode via `yiga.scss`.
- `src/components/BootScreen.vue`: the cold-start screen (mounted by `App.vue`, which mounts the home screen as it dissolves): starts black (like the splash), then the loader's logo ignites once the art of the logo and the frame is decoded (`preloadCritical` in `lib/preload.ts`, so nothing flickers in), `ScanlineOverlay` fades in with it, and `PhoneFrame` (`on` prop, set through the `frame` event) draws in 1.8 s after the logo: the whole stone frame fades in as one piece (corners and strips are only split for responsive sizing, so nothing may animate on its own), then the glow flickers on. No loading bar. It waits for the real preloading (fonts, images, sounds, the lazy route chunks incl. MapLibre), paced by `lib/boot.ts` (pure, tested): 0.9 s black, at least 5 s after the logo, at most 10 s in all, a tap skips after 2.5 s, shorter with `prefers-reduced-motion`. The preload globs are static (Vite requires inline options), so new image folders go into the glob lists in `preload.ts`. Later transitions keep the short `SheikahLoader`.
- `src/components/ScanlineOverlay.vue`: reusable old-tube look (scanlines, dark edges, rolling band in the mode color, flicker). Drop it into any positioned parent and set its `z-index` there, e.g. for the Yiga transition.
- Transitions: `SheikahLoader` plays alone first (`LOADER_MS` in `App.vue`), then the new screen fades in after `--screen-delay` (`variables.scss`: loader hold + its exit; shorter right after the boot, longer after a mode switch), so those three go together. An app can have its own loader look: `loader` on its `apps.ts` entry (`loaderVariantFor`) becomes `SheikahLoader`'s `variant` (the scanner's `lens`: logo tinted purple with `--lens-hue`, purple backdrop, a second ring ping; same timing, and it plays on leaving too). The lens has its own open/close sounds (`lens-on` / `lens-off`, played by `uiSounds` for the `lens` variant). Going straight from one app to another (`state: { direct: true }` on the push, read by `lib/navigation.ts`; the scanner's "select" to the map) plays no loader and no sound; `--screen-delay` is 0.3 s (`Phone-main--direct`: the old app fades out, then the new one plays its own intro, e.g. the map's). A mode switch plays the longer "hack" variant of the loader (scanlines, glitch bursts, the whole logo turns over while the colors fade); `useYigaMode` applies the new colors `MODE_APPLY_DELAY_MS` into it, and `App.vue` keys the router view by mode so the screen is rebuilt after it.
- Map content: `src/game/markers.ts` is the one file to edit. Three kinds: `pois` (icon), `areas` (dotted outline with a real `radiusMeters`, drawn from `metersPerPixel` so it grows with the zoom, plus the `map/area.png` ring and an optional icon) and `regions` (fantasy name, optional runic `caption` in `Sheikah`, optional `scale`; labels share the gold-with-olive-edge-and-glow look of the `map-label` mixin in `MapApp.vue`, colors `--color-map-label*`, also used by the area titles). POIs have a `level` (1 = main, 2 = small: later and smaller; `poiLevels`), an area hides its ring icon and title above `labelMaxZoom` (default `areaLabelMaxZoom`). All take optional `minZoom` / `maxZoom`; `lib/zoomVisibility.ts` fades them. `MapApp.vue` builds each as a wrapper (`App-map-marker`, MapLibre owns its transform and the intro fades its opacity) around a content child that carries the zoom opacity. The samples for areas and regions are placeholders.
- Map intro (`MapApp.vue`, from `--screen-delay`): 1. one grid on the swirl, 2. user marker pops in with a ping (it sits beside the canvas, so only the canvas is clipped), 3. the canvas is revealed by a growing `clip-path` circle from the user, started from the script once the map is `idle` (at the earliest `REVEAL_AFTER_MS` after the delay, at the latest `REVEAL_WAIT_MAX_MS` later; instantly with reduced motion), 4. markers and UI fade in (class `App--revealed`).
- `src/components/FairyOverlay.vue`: the fairy in the camera app, a rose glowing dot with a sparkle trail (sparse and short while she floats, dense and larger when she is excited: `excitement` of the brain) and spatial sound (`useFairySound`: the looping `fairy-float`, whose playback rate varies a little, 0.85 to 1.35, with her speed and nervousness, and one-shot voices `play(voice)`: `hey`, `hello`, `alarm`, `sad`, `move` (3 files), `look` (3 files), `in` (she appears at her hiding place) and `out` (she flies away, 2 files each), all through one 3D panner, so they come from where she is) around the user's head. There is no focus ring: the camera cannot see her, so she shows it herself (nervous shivering, faster flickering glow, more sparkle). Gyro only (`useOrientation`, 3DoF, the smooth relative `deviceorientation`): `lib/fairy.ts` holds the organic path (`fairyPosition`), the phone-rotation maths (`viewBasis`, `worldToCamera`, honours `screen.orientation.angle`), `focusAngleDeg` and the projection; the trail is stored in world space. `CAMERA_VFOV_DEG` and the orientation signs are untested on a real phone: tune there.
- Fairy story: `lib/fairyBrain.ts` (pure, tested) is a state machine fed the view each frame: `swirl` (focus her for 5 s; she is in focus while she is on the screen, inside its central 90%, and gets nervous; first contact: `hello`) -> `escape` (catch me: she hovers in front of the player, world-fixed, and hops 18-30 deg sideways between short pauses, mostly to the other side, sometimes a feint, always within a front arc of the view; keep her 5 s or start over, which plays `sad`) -> `flee` + `hidden` three times (she shoots up and hides behind the player and calls `look` now and then, closer each round, found after 1 s in focus: `alarm`) -> `befriend` (scripted loop in front of the view) -> `guide` (she hovers in the direction of the target, "hey" now and then). It returns the position, fade, glow, loudness and events (`hey`, `burst`, `move`) that `FairyOverlay` draws and plays. All tunables (focus cone, durations, grace times, hide distances) and the guide target (placeholder Residenzschloss) are in `game/fairy.ts`. Nothing is persisted: every visit starts at phase 1. A temporary text link at the bottom ("Fee: ... ▸", marked `TODO(fairy)`) skips to the next phase for testing.
- Compass: `useCompass(target)` (GPS + `useHeading` + `lib/geo.ts`: `distance`, `bearing`, `relativeBearing`, `isFacingTarget`) has no game logic, so the guide fairy, the map's sensor mode and the Sensor app (`feature/sensor-compass`, whose `bearingDegrees` and `isFacing` live in `geo.ts` verbatim) can share it. The fairy's frame has an arbitrary north (relative orientation), so `useOrientation` also reads `deviceorientationabsolute` to track `northOffset` (`lib/northOffset.ts`) and the guide aims at `bearing - northOffset`. Untested on a real phone.
- Sensor mode: the map shows the sensor HUD (only once a sensor was activated, `useSensorMode().used`: it would spoil that there is one; then it stays, "Aus" when switched off) left of the recenter button, centered on it, without a background: the target name (or "Aus") in the size of the clock digits, a runic "Sensor" caption under it and an icon (`images/map/sensor-off.svg` X, `sensor-on.svg` signal); tap = switch off and on again. The last activated sensor stays selected (`useSensorMode`: `selected` + `enabled`, `active` is the selected one while on) until another one is activated. `src/game/sensors.ts` is the one file to edit for the sensor events (id = QR payload, name, image, description, `commonLocations`, `status` `available` | `unavailable` + `statusText`, optional `location`); `scanTargets` is built from it (action `sensor`). Holding a recognised code ~3 s (`HOLD_MS` in `ScanOverlay.vue`, `heldMs` from `createTracker`; the lens ring fills via `--hold`, yellow = `--color-secondary` for everything detected) opens `ScanModal` (its own short fade, not the global `fade`, which waits for the loader; compendium layout: `number name` and a framed picture left, `OrnamentTitle` "Beschreibung" and "Fundorte" right) with the event: "Als Sensor Ziel wählen" + "Abbrechen" (the framed buttons), only "Abbrechen" and the reason when `unavailable`. "Als Sensor Ziel wählen" calls `useSensorMode().activate` (module-level, not persisted, survives leaving the map) and goes to `/map`. `MapApp` runs `useSensorBeeper` (Web Audio, `sensor-signal.ogg`, ≤2 voices): `lib/sensorBeep.ts` (pure, tested) maps distance to the interval (`300 ms` at 10 m to `2.5 s` at 500 m, faster while facing) and volume (louder closer and while facing; rapid pulse within `foundMeters`); all numbers are `sensorTuning` in `sensors.ts`, untested on a real phone. No location on the event: it activates, the sensor HUD is dimmed and nothing beeps. No compass: counts as facing. A code that opened only opens again after it was out of view (a different code opens normally).
- Scanner app (`views/apps/ScannerApp.vue`, route `/scanner`): the camera with one purple-tinted Sheikah look (`game/scanFilters.ts`, plain CSS `filter` on the video plus scanlines; the scanner reads the raw frames, so it never affects detection) that reads QR codes automatically. The payload is the bare target id, a short digit string (`01` to `09`: QR version 1, the smallest a QR code gets, at error correction H); `game/scanTargets.ts` maps it to an action (`ScanAction`: `modal` and `sensor`, run by `useScanAction`). `useCodeScanner` reads the video (native `BarcodeDetector` on Android, jsQR lazy-loaded elsewhere, paced by `requestVideoFrameCallback`) and keeps the latest reading in a plain object. `lib/scan.ts` (pure, tested) holds the maths: `coverMap` (video pixels to the `object-fit: cover` box), `homographyMatrix3d` (the 4 corners to a CSS `matrix3d`, so `ScanOverlay` lies on the code with its skew and rotation), `boxQuad` (a box on the code's plane, in code widths, to its place on screen: the scanner draws only `aroundCode`, a small square on the code; `boxFromLayout` is kept for bigger frames but unused) and `createTracker` (smoothing, hold after a missed reading, confirmation over several readings). Phase one follows one code (the largest); the detector already returns all of them, `TODO(multi)` marks where to follow several. The camera is shown as a round lens (the Lens of Truth): `.App-camera` keeps its full-screen box, so the overlay maths stay as they are, and is cut by `clip-path: circle()` (an iris opening after `--screen-delay`); `LensRim` draws the purple rim (two cheap animated layers) in the `.App-lens` box, and `ScanOverlay`'s `region` (that box) makes codes outside the circle count as not seen (`isInsideCircle`) and receives the hold progress as `--hold` (0..1), which `LensRim` draws as an arc (`detected` recolors it; the recognised code's name shows beside the lens and a tap opens it). The camera sits at one end of the phone, so the lens is shifted away from it by `LENS_SHIFT` (`scanFilters.ts`, signed by `lib/lens.ts` from `useScreenAngle`; a first guess, tune on a phone). No scope icon (`camera.stage($scope: false)`); the entry button sits at the lower right beside the lens. A manual "Code eingeben" field is the fallback. The overlay needs no camera calibration; anchoring in the world (gyro, `lib/fairy.ts`) is not built. `scripts/qr-sheet.mjs` prints a size test sheet and the cards' codes (A4 SVG in mm, print at 100%) to settle how small a code can be printed. Smoothing constants, the filter hue and the native detector's speed are untested on a real phone: tune there.
- `src/components/widgets/`: `ClockWidget` and `WeatherWidget`, each with a runic caption in the `Sheikah` font (`_widget.scss` mixin `label`). They carry no layout of their own: the screen sets `--widget-clock-size` and `--widget-align` (flex alignment) on the widget or its container, as `HomeView` (portrait: clock top, weather bottom; landscape: upper corners) and `MapApp` (stacked top right) do.

## Conventions

- Decorative art scales with one unit, `--u` (`variables.scss`: one source pixel of the 1920x1080 frame art, width-bound on portrait, clamped). Size art as `calc(N * var(--u))`, inset screens from the frame with `--frame-top` / `--frame-bottom`, and keep content beside the corner art with `--frame-corner-tl` / `-tr` / `-br` (corner widths), never with pixel literals.
- Full-screen surfaces (page, install gate, lightbox) get the swirl tile through `@include surface.surface` (`_surface.scss`), which also handles the Yiga tile.
- Styles: SCSS, scoped, BEM-like `Block-element--modifier`. Colors via CSS vars from `src/assets/scss/variables.scss`.
- Every listener, timer, stream and AudioContext must be released in `onUnmounted` (the composables do this).
- Every GPS trigger needs a manual fallback, because GPS is unreliable outdoors.
- Audio needs a user gesture before it can play. Use `playSound()` for effects (swallows the rejection).
- Sounds are `.ogg`.

## Gotchas

- Yiga mode (red UI, own app set): flip phone head-down + shake inside `yigaZone` (`src/game/zones.ts`, placeholder position), shake again to reset. Not persisted. Fallback for bad GPS, also the way to test in a browser: tap the version on the home screen 7 times to toggle the mode directly (no zone, flip or shake). Colors switch via `:root[data-mode='yiga']` in `variables.scss`; baked-in blue images are overridden in `src/assets/scss/yiga.scss` (`*-red` files are script-made placeholders). New apps go in `src/game/apps.ts` with a mode.
- Fonts (`assets/scss/fonts.scss`, all self-hosted, the app is used offline): `Roboto` (latin woff2: 400, 500, 400 italic; `size-adjust: 92%` because it looks bigger than the Open Sans it replaced) is the text font everywhere, `Sheikah` the runes, `HyliaSerif` the headings of the info text. A new weight needs its own file and `@font-face`.
- Vibration and sounds need a prior tap, like all audio.
- The manifest asks for `display: fullscreen` and `orientation: landscape`; Android reads it at install time, so change it means reinstalling (or waiting up to a day for Android to refresh it). `useOrientationLock` (mounted in `App.vue`) also locks landscape from the page, which covers an app installed with an older manifest. Text scales from `--font-base` (`variables.scss`, set on `body`), the art from `--u`.
- `InstallGate` only shows in production builds in a browser tab (any `display-mode` but `browser` counts as the app). After an install from the tab it stays, without "Später", and asks to open the installed app: the tab must not turn into the app. Chrome fires `beforeinstallprompt` once, so `useInstall` captures it at module load.
- Visual checks: build, `npx vite preview`, screenshot with headless Chromium.
- The map needs no API key. Never commit keys.
- MapLibre markers own their element's `transform`: rotate a child element, never the marker element (the user marker rotates one `-heading` child holding the view cone `map/direction.png`, whose tip and lean are constants in `MapApp.vue`, and the arrow). Its worker is wired via `setWorkerUrl` in `MapApp.vue` (without it the map is blank in dev and production).
- Do not edit `dist/`. `dev-dist/` and `*:Zone.Identifier` files are ignored.
- Heading uses `deviceorientationabsolute` (Android only). Test location, heading and camera on a real phone, not only on desktop.
- `src/components/experiments/*.vue_` are old, uncompiled experiments. Reference only.
- Not usable yet, parked on branches: the Web NFC Reader app (`feature/nfc-reader`) and the Sensor app with beeper and bearing maths (`feature/sensor-compass`). The old Sheikah Lens (`feature/camera-scanner`) is superseded by the scanner app.
